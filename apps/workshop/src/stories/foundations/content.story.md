# Content

Keep the following principles in mind when creating UI content for Dusk.

## Be clear

Aim for a seventh-grade or below reading level. This means you should write straightforward text, without trying to be creative with words.

There are some useful tools you can use to test your content for simplicity and reading level:

- [Grammarly](https://www.grammarly.com/)
- [Hemingway](http://www.hemingwayapp.com/)

### Be consistent

Refer to the same actions, sections, labels, landing pages, and so on, the same way across the app. But don’t sacrifice clarity over consistency.

## Content Guidelines

### Acronyms and abbreviations

Use acronyms when they are more widely used than the spelled out term.

### Dates and time

When displaying the datetime, always localize according to the language detected in the app.

### Emojis

Avoid using emojis, but when you do:

- Use them only at the end of a sentence
- Use only well-recognized emojis
- Do not repeat emojis
- Use emojis that will work well in both dark and light modes

### Error messages

- Be friendly and helpful, and avoid jargon. Do not blame the user.
- Be specific.
- Do not apologize in the UI.
- Do not use humor.

### Feedback

Feedback should be clear and reassuring, using the same terms used by the UI elements that triggered it. Don't use humor, and avoid jargon.

### Forms

Use sentence case for form titles, labels, and fields.
Do not include colons in form labels.

### Labels and Buttons

All labels and button text should be in sentence case, and not include punctuation.

Action labels should start with an imperative verb.

Use “sign in” rather than “log in” and prefer "authenticate" over both.

### Links

Link text should be meaningful and unique.

### Numbers

Numbers should be localized according to the language detected in the app.

### Punctuation

Headings, labels, and buttons should not include punctuation. In most cases, exclamation marks are not appropriate.
